> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task runs as two separate `claude` processes (C82): a test worker, then an implement worker, each started in its own worktree with `PITWALL_PHASE` and `PITWALL_WORKER_SCOPE` (CLAUDE.md "Workflow"; memory: worker launch command). Briefs follow `docs/tasks/_template.md`.

**Goal:** each session builds on a chosen basis (practice, qualifying, or none), plans are saved things chosen per race, the planning round is a replayable function, stale storage is rebuilt on use, and the planner's 2026-11-17 root causes are fixed, all before the Texas race on the evening of 2026-11-18.

**Architecture:** the basis follows the calibration-choice pattern (C62a): a session-start value in a sidecar, changed by a recorded `basisChosen` decision; the bridge loads a basis's projections and registers them with the runner before the decision enters, and the engine resolves `view.basis` from the newest decision. A `PlanningRunner` replays a qualifying recording in its own engine instance in a worker. One rebuild service (`ensureCurrent`) owns every rebuild, in a worker, with one storage writer in the main thread. The planner fixes each go to the module that owns the judgement (C43).

**Tech stack:** TypeScript (Node type stripping: no enums, namespaces or parameter properties; relative imports end in `.ts`), pnpm monorepo, vitest + fast-check, better-sqlite3, Svelte 5 (UI), worker threads (the job runner's pattern, `apps/bridge/src/jobs/worker-entry.ts`).

## Review focus

1. **A basis decision whose projections are not registered** (a race replayed after a store was cleared, or a basis naming a session the feed never stored): the run must not throw; `view.basis` lacks that session (C62: "missing from its context") and the replay equals the live run. Pinned in Task 7a-2 (`basis-missing-session.test.ts`).
2. **A rewind past a `basisChosen` decision** (C27a): `view.basis` falls back to the previous choice or the session-start basis at the same frame as in a run that never saw the decision; units recompute. Pinned in Task 0b (`basis-rewind.test.ts`).
3. **Two feeds of one team confirming different bases within a second**: each feed ends with the same newest decision on both (the bridge serialises confirms per team). Pinned in Task 7a-2 (`basis-team-confirm.test.ts`).
4. **A planning round opened while the rebuild worker is busy with a large rebuild**: the round waits at most for the current session's rebuild, then runs before queued first reads (priority). Pinned in Task 7d (`rebuild-priority.test.ts`).
5. **Basis "none" in a race**: `weekend-pace` returns `unknown('insufficientData')` per car, no planning-round data, the live strategy runs from the race's laps, nothing throws. Pinned in Task 6 (`weekend-pace.no-basis.test.ts`).
