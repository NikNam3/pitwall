# SP4.3a The Model and the Scoreboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task has two phases by two agents (contract C82): a test agent writes the failing tests and commits them, an implementation agent makes them pass without touching them. Supervisor steps (marked **supervisor**) commit the contract, contract-first types (C81), data files and gates, and write no logic.

**Goal:** The estimation and the plain forecast the 4.3b decisions will run on: who drives each car (`car-driver`), driver profiles per person, four estimation calculators, the starting-point builder, the lap and race simulators, a synthetic-truth race generator, and `forecast-score` with `pitwall score`. No display.

**Architecture:** A new shared car sub-machine `car-driver` turns the `aiControlled` signal into `ai` and `human` spans; every AI/human split reads them through membership (C26). The bridge owns driver profiles as it owns calibration sets: person files, a profile store cache, a profiles sidecar, `view.drivers` fixed for the run (C62c). The four calculators are quick and written as pure "as of" functions over an `AsOfView` (the projection cut at frame N by the projection module, the situation at N, the run's fixed inputs); their scheduled run calls them at the current frame. `forecast-field` (shared) is the only builder of the simulators' starting point; `lap-model` and `race-forecast` are simulators (C50); `forecast-score` is a job (C51) that rebuilds past starting points and scores plain forecasts against what happened.

**Tech Stack:** TypeScript (Node type stripping), pnpm monorepo, vitest + fast-check, node:sqlite.

**Spec:** `docs/superpowers/specs/2026-11-11-sp4.3a-model-and-scoreboard-design.md` (approved 2026-11-11, with the review's T8 and its approved contract text §2.1). Under it: `docs/superpowers/specs/2026-11-10-sp4.3-strategy-model-design.md` (ideas, algorithm, contract text §6). Research: `docs/research/12-strategy-data-spike.md`, `13-strategy-compute-spike.md`, `14-strategy-reread-after-spike.md`.

## Review Focus

1. **A human drops out online and the AI takes over mid-race** (`human → ai`): the profile counts only the human span's laps, `driver-noise` switches to the AI model from the takeover lap, `forecast-score` files each case under the span at its frame. → Task 4 row 5, Task 10 row 6, Task 6 row 7, Task 19 row 10.
2. **Online names hidden** (empty Participants names, all humans `restricted`): links are by slot, suggestions by race number then team, `view.drivers` is `notApplicable` for every unlinked slot, nothing throws. → Task 6 rows 4, 5; Task 8 row 3.
3. **A rival whose wear is hidden by realism and who has no profile**: its wear rate falls back to our car's measured rate on that compound, then the config default; `forecast-field` never emits `NaN`; the source says which. → Task 10 row 7, Task 16 row 4.
4. **A flashback across a stop or the leader's crossing**: every calculator's output and the as-of builds after the rewind equal a run that never received the undone frames; the `forecast-score` job is cancelled and re-triggered (C30, C33). → Tasks 9–12 row "rewind", Task 19 row 9.
5. **A race before any peer stop, a car that owes no stop, a car out of sets**: `rival-stops` gives `tyre-life`'s window, an open window to the flag, no throw. → Task 11 rows 2, 3, 4.
6. **A recording of a session with 0 completed laps or no race phase** given to `pitwall score`: it prints the tables with counts 0 and exits 0. → Task 20 row 4.
