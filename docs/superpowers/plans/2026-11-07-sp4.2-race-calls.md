# SP4.2 Race Calls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task has two phases by two agents (contract C82): a test agent writes the failing tests and commits them, an implementation agent makes them pass without touching them. Supervisor steps (marked **supervisor**) commit contract-first types (C81), stubs, data files and gates, and write no logic; a minor change (C82) is the supervisor's in one commit.

**Goal:** Three snapshot race calls (`rejoin`, `sc-call`, `pit-window` with the `window` moment) and their displays (`crossing-order`, `sc-card`, `pit-window-strip`, ghost lines on the gap chart, the ghost on the track map) in a new `strategy` workbook; the scheduler cadence `ourCrossing`.

**Architecture:** Three quick analyses over the view. `rejoin` (cadence `ourCrossing`) reads `gaps` and `pit-loss` and places a ghost of each of our cars "in the pit lane now" per condition; `sc-call` reads `rejoin` (one rejoin judgement, C43); `pit-window` reads `tyre-life`, the tyre sets and the compound rule and owns the window judgement that `race-moment` maps to the `window` moment. Displays render topic values (C65); the pit-window strip's label placement is a pure layout module with a property test.

**Tech Stack:** TypeScript (Node type stripping), pnpm monorepo, vitest + fast-check, Svelte 5, Playwright.

## Review Focus

1. **Lapped cars right behind us:** a car a lap down within the loss is traffic in the crossing order but never changes the rejoin position; a car a lap up stays ahead. → Task 6 row 4.
2. **The first lap of a race and a loss longer than our recent crossings:** the map point is `insufficientData`, the order still computes, nothing throws. → Task 6 row 7.
3. **The last laps:** `latest` is capped at `flag − 1`; on the final lap there is no window and no `window` moment; a stint that reaches the flag with the rule met has no sets. → Task 5 rows 3, 8.
4. **Both our cars:** each has its own `rejoin.car`, `scCall.car`, `pitWindow.car`; ghost lines carry the car; our teammate appears as an ordinary row in our crossing order. → Task 6 row 9, Task 13 row 2.
5. **An SC or VSC coming out while we are in the pit lane:** `rejoin` and `sc-call` are `notApplicable` (`boxStop`), the card shows its unknown state, nothing throws. → Task 6 row 8, Task 7 row 3.
6. **A flashback across a stop:** `ourCrossing` is due on a rewind; the quick units equal a run without the undone frames (generic properties). → Task 2 row 3, Task 15 gates.

```ts
// domain/analyses/rejoin.ts
/** One row of a crossing order: a car (or the ghost, our own car id with ghost: true), its race position, the gap to the row ahead (positive = behind). */
export type CrossingRow = { carId: CarId; position: number; intervalMs: Known<Ms>; ghost: boolean };
/** Our car as if it were in the pit lane now, under one condition. */
export type RejoinAt = {
  condition: PitCondition;           // 'green' | 'sc' | 'vsc'
  lossMs: Known<Ms>;
  lossSource: EstimateSource;
  rejoinPosition: Known<number>;
  order: CrossingRow[];              // physical order, `orderAround` cars either side of the ghost, the ghost row included
  mapPoint: Known<MapPoint>;         // notApplicable without a track file
};
export type Rejoin = { carId: CarId; position: number; conditions: Record<PitCondition, RejoinAt> };
/** `rejoin.ghostLines`: per our car and condition, our gapper line over the last `ghostLaps` laps plus the loss. */
export type GhostLines = { lines: { carId: CarId; condition: PitCondition; points: { lap: number; gapMs: Ms }[] }[] };

// domain/analyses/sc-call.ts
export type ScCallRow = { condition: 'sc' | 'vsc'; rejoinPosition: Known<number>; lossMs: Known<Ms>; lossSource: EstimateSource; gainMs: Known<Ms> };
export type ScCall = { carId: CarId; rows: [ScCallRow, ScCallRow] }; // sc, then vsc

// domain/analyses/pit-window.ts
export type PitWindowState = 'before' | 'lead' | 'open' | 'closed' | 'none';
export type PitWindowSet = {
  compound: VisualCompound;
  sameType: boolean;                 // dry for a dry fitted set; inter or wet for an inter or wet one
  lifeLaps: Known<number>;
  earliest: Known<number>;           // a stop lap
  lifeEnd: Known<number>;            // latest + lifeLaps
  reaches: boolean;                  // lifeEnd ≥ flag
};
export type PitWindow = {
  carId: CarId;
  flag: number;                      // totalLaps
  currentLap: number;
  stint: { compound: VisualCompound; fromLap: number; latest: Known<number> };
  sets: PitWindowSet[];
  window: PitWindowState;
  windowCompound: Known<VisualCompound>; // the first same-type compound with a window; notApplicable for 'none'
};
```
