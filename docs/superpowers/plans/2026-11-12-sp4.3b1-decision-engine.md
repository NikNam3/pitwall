# SP4.3b1 The Decision Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task has two phases by two agents (contract C82): a test agent writes the failing tests and commits them, an implementation agent makes them pass without touching them. Supervisor steps (marked **supervisor**) commit the contract, contract-first types (C81), data files and gates, and write no logic.

**Goal:** Repair the plain forecast until it beats "gaps stay as they are", then build the decision engine on it: `race-hazard`, `strategy-dp`, `race-monte-carlo`, the `strategy` job for both our cars, the plan decision, `pitwall strategy` and CRPS in `forecast-score`. No display (4.3b2).

**Architecture:** Part 0 fixes the 4.3a forecast (F1–F8) and ends with the supervisor's U9 check on four dry races. Then a quick calculator `race-hazard` turns the track file's per-lap SC/VSC chances into the remaining race's hazard; two simulators (C50) `strategy-dp` (per car, stops and compounds, expected over SC/VSC) and `race-monte-carlo` (policies over CRN scenarios, adaptive under a cap) run inside the `strategy` job (C51), whose `prepare` builds the starting point through `forecast-field`. Plans the user commits are decisions (C76).

**Tech Stack:** TypeScript (Node type stripping), pnpm monorepo, vitest + fast-check, worker threads (the existing job runtime).

**Spec:** `docs/superpowers/specs/2026-11-12-sp4.3b-decisions-under-uncertainty-design.md` (approved 2026-11-12 with the review fixes, U10 to U12; contract text §2.1–§2.4 approved). Under it: `docs/superpowers/specs/2026-11-10-sp4.3-strategy-model-design.md`; 4.3a: `docs/specs/2026-11-11-sp4.3a-model-and-scoreboard-design.md`. Research: `docs/research/13`–`16`.

## Review Focus

1. **The lobby SC setting is Off** (or the track file has no hazard): `race-hazard` gives zero chances (Off) or `notApplicable` (no hazard), the DP equals the deterministic DP, the Monte Carlo draws no neutralisation, `strategy` still ranks and its metadata names the hazard's state. → Task 14 row 5, Task 15 row 4, Task 18 row 9.
2. **No plan is possible** (out of new sets, the compound rule unsatisfiable, one lap left): the DP returns only "stay out" (or "box this lap" when the rule still demands a stop and a set exists), nothing throws, the job ranks one or two rows. → Task 15 rows 6, 7; Task 18 row 10.
3. **A flashback while the `strategy` job runs, across a plan commit**: the job is cancelled and re-triggered, the voided `planCommitted` no longer counts, the re-run equals a run without the undone frames (C27a, C30, C33). → Task 17 row 3, Task 18 row 7.
4. **Both our cars committed, or a car retired mid-race**: no search rounds for committed cars, their rows still ranked (U3); a retired car of ours gets `notApplicable` and the other is planned alone. → Task 18 rows 4, 11.
5. **A stop under an SC in the forecast's start lap** (the car is in the pit lane at the predict frame): F2's in-lap/out-lap split does not double-count the loss; `rival-stops` (F3) gives the car no second stop at once. → Task 6 row 3, Task 7 row 3.

6. **Two feeds of one team, a commit in one of them** (and a third feed of another team): both logs and both sidecars hold the plan, each at its own frame; each recording replayed alone gives the same `latestPlan`; the other team's feed never gets it; a feed that joins later gets the newest plans; a `calibrationChosen` stays with its feed. → Task 2b rows 3–6, Task 17 rows 7–10, Task 20 row 5b.
