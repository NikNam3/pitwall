# SP4.3c One Owner per Judgement: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task has two phases by two agents (contract C82): a test agent writes the failing tests and commits them, an implementation agent makes them pass without touching them. Supervisor steps (marked **supervisor**) commit contract-first types (C81), data files and gates; logic in supervisor-owned files is a named delegated change in two phases (C78).

**Goal:** Give every judgement in the codebase exactly one owner, move every reader onto it and delete every other copy; fix the strategy (no-stop plan, weather, per-compound tyres, the 70 % limit) and the 2026-11-14 live-test findings (gap chart, ghosts and codes, restart, tyre bands, default workbooks) as part of it.

**Architecture:** Six steps, bottom-up (spec §6). Step 1 adds shared helpers and vocabulary with no number change; step 2 gives the small judgements their owners and fixes the contract breaks; step 3 is the supervisor's domain, recorder, restart and track-data work; step 4 builds the models (`tyre-model` with one module per tyre type, pace, track condition and the `weather-paths` simulator); step 5 rebuilds the strategy's stop, rival and plan logic on them; step 6 the displays and tooling. Approach A (spec §4): every task moves all readers of its judgement and deletes the old copies before it merges to `sp4.3c/integ`.

**Tech Stack:** TypeScript (Node type stripping), pnpm monorepo, vitest + fast-check, Svelte UI, Playwright, SQLite storage, worker threads.

**Spec:** `docs/superpowers/specs/2026-11-14-sp4.3c-consolidation-design.md` (approved by the user 2026-11-14 with review fixes 211f368a; contract C59 3568482e and C47 1875c349). ## Review Focus

1. **A rival under realism with every tyre value hidden** (wear, sets, temperatures `unknown('realism')`): `tyre-model` gives its rates from our own car's game values on that compound with source `game`, the heat term off; nothing throws; `strategy` still plans. → Task 12 row 9.
2. **A set already past the limit when the engine joins** (wear 74 % at a restart): laps to the limit 0, `pit-window` says stop now, the DP's only plans stop at once, the MC never runs the stint further. → Task 12 row 10, Task 19 row 6.
3. **A recording cut mid-record by a crash, then a restart**: the bridge trims to the last whole record, the replay equals a run of the trimmed file, the new packets follow the resume record, and `pitwall reprocess` of the continued file equals the live run. → Task 10 rows 2, 5, 6.
4. **A forecast with no rain chance at all** (or no forecast reaching the view): `weather-paths` gives one path for every u, the DP solves once (not K times), the candidates are not doubled. → Task 14 row 6, Task 19 row 4.
5. **A race joined after lights out under a safety car**: the gap chart starts at the leader's first crossing after the join with the join marked; `race-hazard` reads the open, confirmed SC; the time-loss exclusion skips the SC laps; nothing reads a race start that does not exist. → Task 4 row 4, Task 6 rows 2–3.
