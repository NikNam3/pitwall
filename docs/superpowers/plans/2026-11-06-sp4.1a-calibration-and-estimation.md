# SP4.1a Calibration and Estimation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task has two phases by two agents (contract C82): a test agent writes the failing tests and commits them, an implementation agent makes them pass without touching them. Supervisor steps (marked **supervisor**) commit the contract, contract-first types (C81), data files and gates, and write no logic.

**Goal:** The engineer builds per-track calibration sets from stored sessions and picks one per session; `degradation`, `tyre-life` and `pit-loss` start from it and take over from the session's laps; the stint scatter, the pit-loss table and the calibration panel show them in a new `garage` workbook.

**Architecture:** Calibration sets are user-authored files the bridge owns; estimation units declare pure `aggregate` functions (`definePriors`) that the bridge's priors store runs over stored projections and caches. A run starts on a preselected set (`view.priors`, sidecar); a different pick is the first decision kind (`calibrationChosen`), recorded by a new decision recorder and replayed from a decisions sidecar. The three calculators are quick, read `view.priors`, and two analyses publish their topics.

**Tech Stack:** TypeScript (Node type stripping), pnpm monorepo, vitest + fast-check, node:sqlite, Svelte 5.

**Spec:** `docs/superpowers/specs/2026-11-06-sp4.1a-calibration-and-estimation-design.md` (approved by the user, 2026-11-06). The contract `docs/architecture.md`; answers A20–A28 in `docs/superpowers/specs/2026-11-05-sp4a/00-carry-over.md` §9; mockups `docs/design/2026-10-30-sp4a-displays/4-longrun.html`.

## Review Focus

1. **A session on a track with no calibration set and no track-file defaults** (`view.priors` and `view.track` both `notApplicable`): `degradation` starts from the config default with source `default`, `pit-loss` gives `unknown('insufficientData')` until a measured stop, never `NaN`. → Task 6 row 6, Task 7 row 7.
2. **A source whose stored session was deleted or became stale** (rebuild pending, C61): the store skips it with a reason on `calibration.values`, never throws, and the set's value rests on the rest. → Task 5 row 8.
3. **A flashback that voids a `calibrationChosen` decision**: `view.priors` returns to the session-start sidecar's entries, and the topics equal a run that never received the pick (C27a, C33). → Task 4 row 4.
4. **An override outside its declared range** (`calibration.override.set` with `deg 5000`): the bridge rejects it with a reason and stores nothing (C73). → Task 5 row 5.
5. **A stint of one lap or a stint with only in- and out-laps** as a source: its aggregate is `insufficientData`, the set ignores it for pooling, the panel shows why. → Task 6 row 8.
