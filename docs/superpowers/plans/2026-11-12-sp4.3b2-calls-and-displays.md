# SP4.3b2 Calls and Displays Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task has two phases by two agents (contract C82): a test agent writes the failing tests and commits them, an implementation agent makes them pass without touching them. Supervisor steps (marked **supervisor**) commit contract-first types (C81), stubs, mechanical ports and gates, and write no logic; a minor change (C82) is the supervisor's in one commit.

**Goal:** The three race calls on the 4.3b1 decision engine (`undercut`, `pit-sweep`, `sc-call` as a job), the strategy table, undercut card, pit sweep table and SC card change in the `strategy` workbook for both our cars, the drivers panel and the preferred calibration set in the garage, the shell without the session-start prompt; then the SP4.3b gates and the merge to main.

**Architecture:** Each call is an analysis with a small Monte Carlo job (C51): `prepare` builds `strategy`'s input (moved to `analysis/src/shared/strategy-input/`) plus the call's own reads; `run` solves `strategy-dp` once per car (`solveDp`), forces the call's stops, takes the continuation from that solution with `bestWith`, and scores every case on common scenarios with `race-monte-carlo`'s new `scoreCalls`, to the call's horizon, under a scenario-policy cap (a count, never a clock). Job outputs are keyed by our cars; `bindJob` gains a `select` so every call topic is per car. Displays render topic values only (C65), with the distribution strip as one kit piece.

**Tech Stack:** TypeScript (Node type stripping), pnpm monorepo, vitest + fast-check, worker threads (the existing job runtime), Svelte 5, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-12-sp4.3b-decisions-under-uncertainty-design.md` §9, §10, §11, §12 (with the mockup fixes of 12c23611 and the uiAction additions of the plan review, §10). Mockups (approved, Q1–Q10 answered): `docs/design/2026-11-12-sp4.3b/` (`README.md`, `strategy-table-b.html`, `undercut-card.html`, `pit-sweep-table.html`, `sc-card.html`, `drivers-panel.html`, `calibration-panel.html`, `strategy-workbook.html`; `gen.mjs` draws them and holds the sample numbers). It builds on the 4.3b1 plan `docs/superpowers/plans/2026-11-12-sp4.3b1-decision-engine.md`, whose Task 3 and Tasks 17–20 define the names used here.

```ts
  untilLap: number | null /* the scenario stops at our crossing of this lap; null = to the flag */ };
type CallInput = { start: StartingPoint; car: CarId; candidates: CallCandidate[]; committed: Record<CarId, Policy | null>;
  hazard: McInput['hazard']; rivalRules: RivalRules; scenarios: number; traffic: { gapMs: Ms; laps: number } };
type CallOutcome = { finish: Int8Array /* position at untilLap, else at the flag */; rejoin: Int8Array /* -1: no stop */; traffic: Int8Array;
  gapMs: Float64Array | null /* rival's race time minus ours at its gapAtLap crossing: positive = we ahead */;
  raceMs: Float64Array /* race time at untilLap, else at the flag */ };
type CallResult = { outcomes: CallOutcome[] };   // per candidate, per scenario; scenario i is the same draw for every candidate (CRN)

// strategy-dp/types.ts (4.3b2)
type DpSolution = { readonly input: DpInput; /* the solved value table over the DP's state, opaque to callers */ };
type DpFirst = { stopLap: number; compound: NoiseCompound | 'best' } | { noStopThrough: number };
type DpUnder = { condition: 'sc' | 'vsc'; remaining: Float64Array };   // a neutralisation forced at the start lap, its laps-left pmf
```
