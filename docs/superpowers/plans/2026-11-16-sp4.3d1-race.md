# SP4.3d1 The Race: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task has two phases by two agents (contract C82): a test agent writes the failing tests and commits them, an implementation agent makes them pass without touching tests or `gallery.ts`; the supervisor checks `git diff --stat <test-commit>..HEAD -- '*.test.ts' '**/test/**' test-support` is empty after every implement phase.

**Goal:** Plans become stop lists in named slots, scored live beside the DP's best per stop count; our car's SC/VSC reaction in the Monte Carlo is the DP's averaged move; the decision card answers stay / box S M H I W for SC, VSC and GREEN every lap; the circle of doom and the strategy overview show the field live; two workbooks (`plan`, `strategy`).

**Architecture:** Bottom-up (C81): contract line and domain types first, then the model change (triggers deleted, the reaction), the job's slots, the calls, the per-frame rejoin and the two new analyses, the bridge's plan routing, then the displays and workbooks. Every judgement keeps one owner (C43): the DP owns "the best move for a state", `rejoin` owns the rejoin position and order, the shared crossing-history helper owns "where our car was when".

**Tech Stack:** TypeScript (Node type stripping), pnpm monorepo, vitest + fast-check, Svelte UI, Playwright, worker threads.

**Spec:** `docs/superpowers/specs/2026-11-16-sp4.3d-planning-design.md` (approved 2026-11-16, contract texts §9.1 and §9.2 included; this plan builds §5, §6, §9.1). Mockups (approved): `docs/design/2026-11-16-sp4.3d/` (`plan-board.html`, `sc-card.html`, `strategy-overview.html`, `circle-of-doom.html`, `plan-workbook.html`, `strategy-workbook.html`; README "What is drawn").

## Review Focus

1. **A saved plan whose stop lap passed before the engine joined** (bridge restart at L20, slot B's first stop L18): its row is `infeasible`, followed as far as it can be (boxes this lap), never dropped, its ΔPOS still against the active plan. → Task 5 row 4.
2. **An old recording whose decisions sidecar holds `planCommitted` with triggers** replays without throwing; the triggers are dropped; the commit is the active plan with no slot. → Task 3 row 6.
3. **A car with every stop used or no set of a compound left** (three stops done; no mediums left): the reaction says stay, the decision card shows "no set", nothing boxes onto a compound it has no set of. → Task 4 row 4, Task 6 row 3.
4. **The teammate's feed joins after slots were saved:** it is handed every slot's newest decision and the active plan, so both boards match. → Task 10 row 3.
5. **The first lap, a join mid-race, or a retired car:** our crossing history shorter than the time asked → `insufficientData`, never NaN or a wrong angle; a car not competing is left off the circle and the overview. → Task 7 row 3, Task 8 row 4, Task 9 row 4.
