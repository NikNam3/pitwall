# SP4.3f: planning out of session: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo every task runs as two separate `claude` processes (C82): a test worker, then an implement worker, each started in its own worktree with `PITWALL_PHASE` and `PITWALL_WORKER_SCOPE` (CLAUDE.md "Workflow"; memory: worker launch command). Briefs follow `docs/tasks/_template.md`.

**Goal:** case B in the panel. On a bridge that has seen no session, the user picks a stored qualifying (which brings its team and cars) and its practice, sets laps, sets and the race's forecast on the plan board, plans and saves. Case A keeps working with every pick preselected.

**Architecture:**
- The stored sessions become a global core topic (`plans.sessions`), listed from storage without a rebuild.
- `plans.round.open` names a qualifying and its team. The planning runner takes the round's team, track and cars from that stored qualifying, never from a feed's remembered seat, which is deleted.
- The race's forecast becomes a race assumption: imported from the qualifying's `nextForecast` by the replay, or entered on the board. It replaces `nextForecast` once, in `asOfEnded`, so every planning reader follows it.
- The round's profile snapshot is built from the current links and handed to the replay in place of the recording's sidecar.
- The shell resolves `player`/`teammate` from the open round when no session runs.

**Tech stack:** TypeScript (Node type stripping: no enums, namespaces or parameter properties; relative imports end in `.ts`), pnpm monorepo, vitest + fast-check, better-sqlite3, Svelte 5, Playwright (+ Electron), worker threads.

**Spec:** `docs/superpowers/specs/2026-11-18-sp4.3f-planning-out-of-session-design.md` (approved 2026-11-18; correction `cf1e1814`). The contract change is committed (`0c731ae3`): read the glossary terms "race assumptions", "planning round", "saved plan", and C4, C1a, C3, C54, C61, C62, C62c, C62d, C65, C72, C73, C84.

## Review focus

1. **A qualifying stored by both of the team's feeds** (two rows, same ref, same team): `plans.sessions` lists it once for the team. The round replays the first row in start order, and either recording shows both cars (realism masks only rivals). Pinned in Task 1 (`plans-sessions.test.ts`, "two feeds, one entry") and Task 3 (`round-from-picks.test.ts`, "replays the first row").
2. **A practice stored for another team picked with the qualifying** (a crafted uiAction, the picker never offers it): rejected `invalid` and nothing opens, with no partial round and no last-choice write. Pinned in Task 3 (`round-from-picks.test.ts`, "another team's practice").
3. **A qualifying with no race samples** (a one-session lobby, `nextForecast` `[]`): the round's forecast rows are `unknown('notReceived')`, the board shows them as missing, `rainPct` is unknown, and nothing reads 0 % (C3). Entering rows makes them known. Pinned in Task 2 (`as-of-conditions.test.ts`), Task 3 and Task 7.
4. **Reopening the same qualifying after entering conditions**: the entered rows, laps and sets stay, and a different qualifying starts from the defaults. Pinned in Task 3 (`round-reopen.test.ts`).
5. **A bridge restart between planning and the race**: the saved plan with its `computedOn.forecast` and profile fingerprint survives, and a race start of the same team preselects it. Pinned in Task 8 (the E2E's restart step).
