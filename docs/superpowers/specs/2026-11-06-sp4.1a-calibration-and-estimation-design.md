# SP4.1a: calibration and estimation

Status: design approved by the user in the 4.1 brainstorm, 2026-11-06 (sections 1 to 3; answers A20 to A28 in `2026-11-05-sp4a/00-carry-over.md` §9). The second SP4 section (`2026-11-05-sp4a/01-sp4-sections.md`), cut from 4.1 together with 4.1b (long run and weather).

## 1. Goal

The engineer builds **calibration sets** from the data of stored sessions (test runs, practice long runs, earlier races), curates them as the car and the driver change, and chooses one for each session. On that base, three estimates exist afterwards that do not exist now, each starting from the calibration and taking over from this session's own laps:

- **degradation**: tyre pace and degradation per lap, per car and stint;
- **tyre life**: laps until the current set reaches its limit, and the fresh-set life per compound;
- **pit loss**: the time a stop costs, per condition (green, VSC, SC).

They are shown in the stint scatter, the pit-loss table and the calibration panel, in a new `garage` workbook. Every value that rests on calibration or a default carries the source badge.

**Not in 4.1a:** raising average, lap overview, weather, crossover and the `longrun` workbook (4.1b); `lap-model`, `race-forecast` and the lap-time cost per wear % (4.3); the race-strategy tools of the `garage` workbook (4.3); a calibration that transfers across tracks (A24).

**Rules for every unit** (carry-over §9): positive = good for our car (A6); each unit updates when its inputs change and its spec states why (A2); track geometry is never computed live (A3).

## 3. Calibration

### 3.1 Calibration sets

A set is a file `PITWALL_DATA_DIR/calibration/<trackId>/<setId>.json` (user-authored, the source of truth; not a cache). `CalibrationSet` in `packages/domain/src/calibration.ts` (supervisor):

```ts
export type CalibrationSource = { sessionUid: SessionUid; feedCar: CarId; stint: number; excludedLaps: number[] }; // stint = its index among the car's stints
export type CalibrationSet = {
  id: string;            // kebab-case, unique per track
  trackId: number;
  name: string;          // the user's label
  createdAt: string;     // ISO date, shown only; never in a view (C35)
  sources: CalibrationSource[];
  overrides: Record<string, number>; // priors key → value, e.g. "degradation.nuMsPerLap.medium"
  lastUsedAt?: string;   // set by the bridge when a run starts on it or picks it
};
```

uiActions (contracts package, C73; the bridge validates each against the set's track and the stored sessions, and rejects an invalid one with a reason the UI shows): `calibration.set.create { trackId, name }`, `calibration.set.copy { trackId, setId, name }`, `calibration.set.rename`, `calibration.set.delete`, `calibration.source.add { …, source }`, `calibration.source.remove`, `calibration.lap.exclude` / `include { …, source, lap }`, `calibration.override.set { …, key, value }` (number, within the key's declared range), `calibration.override.clear`, `calibration.choose { feedId, setId | null }`.

A source must be a stint of a stored session on the set's track, of the feed's player car or its teammate (our cars' data only: rivals' wear and fuel are hidden under realism).

### 3.2 The priors store

- Each estimation unit declares its priors entries in its own folder (`priors.ts`): `definePriors(unit, { key: { version, range, aggregate } })`, where `aggregate(sources: StoredSource[], overrides) → Known<value>`; a `StoredSource` is the source's stint with its laps (minus excluded ones), the session's stops and its track file, read from the stored projection.
- The bridge holds the store in `PITWALL_DATA_DIR/priors.sqlite`: per set and key, the value, its version and the inputs' fingerprint (sources, overrides). A version or fingerprint mismatch recomputes the entry. It recomputes on a calibration edit, at session end (a new stored session may be a source), and on a rebuild (C61).
- Per source it also keeps the source's own fit (its own `aggregate` over that one source) and its residual against the set's value, for the panel (drift, A23).
- Suggestions: the stints of stored sessions on the track, of our cars, with at least 5 `forPace` laps, not in the set; this weekend's first, then newest first.

### 3.3 Choosing a set for a run

- **Preselection** at session start: the track's set with the newest `lastUsedAt`; else the set with the newest source session; else none (`view.priors` `notApplicable`, every estimate starts from the track file's defaults, `ᵈ`).
- The run starts on the preselection at once (C62a); its entries are the sidecar `<recording>.priors.json` (C59).
- **The prompt:** when a new session starts, the UI opens an overlay listing the track's sets, the preselection marked, and `defaults`. Picking another sends `calibration.choose`; the bridge appends a decision `calibrationChosen { setId, entries }` at the current frame (C10, C76) and writes it to the decisions sidecar. Closing the prompt keeps the preselection. The command `calibration.pick` opens it at any time (C72).
- A flashback that voids the decision voids the switch (C27a): `view.priors` follows the projection.
- **Top bar:** the active set's name, or `defaults`; a click invokes `calibration.pick`.

## 4. Estimation units

All three are quick calculators (C41): from scratch over the projection they cost microseconds per frame on the long-race builder, so the C31 exception is not needed. Each holds a behaviour table over the sub-machines it reads (C44).

### 4.1 `degradation`

- **Model:** a Kalman filter per car and stint (Cappello & Hoegh). State: tyre pace `α` and degradation per lap `ν`; observation: the fuel-corrected lap time `lapTimeMs − γ · fuelKg`, `γ` = `gammaMsPerKg` 30 (Bonomi et al. 2023). Fuel from the lap record; unknown (a rival under realism) → `fuelAtStart − burn · lapsDone`, burn from our car's `fuel` rate, else `fallbackBurnKgPerLap` 1.8.
- **Laps:** `forPace` laps only (`lap-classes`). A lap slower than the prediction by more than `outlierSd` 2.5 sd is down-weighted (its observation noise × `outlierNoiseFactor` 10); a faster lap never is.
- **Stint start:** the prior from `view.priors` for the stint's compound (`α` offset, `ν` with sd), else the track file's compound offset with `ν` `defaultNuMsPerLap` 60 and sd `defaultNuSdMs` 60 (`ᵈ`).
- **Basis:** `wear` when the car's wear is visible, else `age`.
- **Output per car and stint:** `basePaceMs`, `nuMsPerLap` with `sdMs`, basis, wear rate per corner (`per-lap-rate`), source (`session` / `calibration` / `default` with the blend parts), and per lap `used | downWeighted | excluded(reason)`.
- **Cadence:** on `laps`, `stints`, `pitStops` (every completed lap of any car: the lap is the finest correct input, A2).
- **Priors entries:** per compound `degradation.alphaOffsetMs.<compound>`, `degradation.nuMsPerLap.<compound>`, `degradation.nuSdMs.<compound>`: the filter run over each source stint, pooled by inverse variance; overrides replace the pooled value.

### 4.2 `tyre-life`

- **Current set, per car:** laps to the limit. Wear basis: per corner the laps until `wearLimitPct` 70 at its rate (today's `tyre-wear` logic, moved here); the worst corner limits. Age basis: the age at which `ν · age` reaches `ageLossLimitMs` 2000, minus the current age.
- **Fresh-set life per compound:** from the priors' wear rates (laps from 0 to the limit), else from `ν` (age basis), else `unknown('insufficientData')`. For 4.2's pit window.
- **Priors entries:** `tyreLife.wearPerLapPct.<compound>.<corner>`; overrides `tyreLife.wearLimitPct`, `tyreLife.ageLossLimitMs` (per set).
- **The port (C43):** `tyre-wear` becomes a thin analysis that publishes `tyreWear.car` from `tyre-life`'s output, the topic unchanged; its readers (`alarms`, the corner block, the tyre-life bar) do not change. Its tests are ported to `tyre-life` where the judgement moved, never dropped (C82). This also makes `tyre-wear` an analysis, as its topic requires (C42).

### 4.3 `pit-loss`

- **Per stop of every car:** loss = in-lap + out-lap − 2 × the car's median `forPace` lap of the `referenceLaps` 3 before the stop (TUM); the stationary time above the session's median stationary time is removed and kept apart. A stop without a clean reference is left out and counted (`noReference`).
- **Condition:** the stop record's `flag` (green, VSC, SC).
- **Per condition:** `(n · sessionMedian + k · prior) / (n + k)`, `k` = `priorWeightStops` 2, `n` the session's stops of that condition; the prior is `view.priors`' value, else the track file's default. Source and parts carried (`2 stops + calibration`).
- **Priors entries:** `pitLoss.ms.<condition>`: the median over every stop of the sessions that give the set a source; overrides replace it.
- **Cadence:** on `pitStops`, `laps`.

### 4.4 Source badge (kit piece)

One cell after a value that rests on a prior: no mark = measured this session (the session's share of a blend above half: for `pit-loss` `n / (n + k)`, for `degradation` the share of `ν`'s posterior precision that its laps added, `1 − posteriorVar / priorVar`); `ᶜ` = calibration (hover: the set's name and its sources); `ᵈ` = default (hover: the track file's source note). Every badged value carries the hover with its parts. Replaces the mockups' `ˢ` (A27).

## 8. Testing

- **Contract:** the guarded views (C41), behaviour tables (C44), presentation tables of the displays that read situations (C66) through the generic completeness tests.
- **`degradation`** (builders): a synthetic stint with constant `ν` recovers it within 10 %; a slow outlier is down-weighted, a fast lap never; a stop starts the next stint from the prior; without priors the default with source `default`; a rival under realism has basis `age`.
- **`tyre-life`**: the ported `tyre-wear` cases; the age basis; fresh-set life from priors and without.
- **`pit-loss`**: TUM arithmetic on a hand-built stop; the stationary correction; `noReference`; the blend at n = 0, 1, 2; a segment test on a real green stop (loss exceeds the pit-lane time) and one on a VSC or SC stop (classed by condition) (C84).
- **Calibration store** (bridge, temporary data dir): aggregate determinism; a version or fingerprint mismatch recomputes; deleting the store loses nothing; every uiAction's validation and rejection; preselection order.
- **Decisions:** a replay with a decisions sidecar equals the live run (C38, stream hash); a flashback that voids a `calibrationChosen` restores the earlier priors (C27a, C33 property); no accumulator reads priors (type).
- **Budgets** on the long-race builder: each calculator < 1 ms per lap update.
- **UI:** component tests for the panel's actions, the prompt and the top-bar name; one screenshot baseline per new display size within the budget (`SCREENSHOT_BUDGET`).
