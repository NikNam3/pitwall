## 1. Goal

The engineer builds **calibration sets** from the data of stored sessions (test runs, practice long runs, earlier races), curates them as the car and the driver change, and chooses one for each session. On that base, three estimates exist afterwards that do not exist now, each starting from the calibration and taking over from this session's own laps:

- **degradation**: tyre pace and degradation per lap, per car and stint;
- **tyre life**: laps until the current set reaches its limit, and the fresh-set life per compound;
- **pit loss**: the time a stop costs, per condition (green, VSC, SC).

They are shown in the stint scatter, the pit-loss table and the calibration panel, in a new `garage` workbook. Every value that rests on calibration or a default carries the source badge.

**Not in 4.1a:** raising average, lap overview, weather, crossover and the `longrun` workbook (4.1b); `lap-model`, `race-forecast` and the lap-time cost per wear % (4.3); the race-strategy tools of the `garage` workbook (4.3); a calibration that transfers across tracks (A24). The old C62a's season-wide model parameters have no home in the new one: if 4.3's lap model needs parameters calibrated across tracks, 4.3 brings its own contract change.

**Rules for every unit** (carry-over §9): positive = good for our car (A6); each unit updates when its inputs change and its spec states why (A2); track geometry is never computed live (A3).

## 3. Calibration

### 3.1 Calibration sets

A set is a file `PITWALL_DATA_DIR/calibration/<trackId>/<setId>.json` (user-authored, the source of truth; not a cache). `CalibrationSet` in `packages/domain/src/calibration.ts` (supervisor):

```ts
export type CalibrationSource = {
  sessionUid: SessionUid; weekendId: string; feedCar: CarId; // the stored session's key (C60)
  car: CarId;            // the stint's car in that session: the feed's player car or its teammate
  firstLap: number;      // the stint's first lap (`StintRecord.firstLap`): stable across a rebuild, unlike a list position
  excludedLaps: number[];
};
export type CalibrationSet = {
  id: string;            // kebab-case, unique per track
  trackId: number;
  name: string;          // the user's label
  createdAt: string;     // ISO date, shown only; never in a view (C35)
  sources: CalibrationSource[];
  overrides: Record<string, number>; // priors key → value, e.g. "degradation.nuMsPerLap.medium"
  lastUsedAt?: string;   // set by the bridge when a run starts on it or picks it
};
```

uiActions (contracts package, C73; the bridge validates each against the set's track and the stored sessions, and rejects an invalid one with a reason the UI shows): `calibration.set.create { trackId, name }`, `calibration.set.copy { trackId, setId, name }`, `calibration.set.rename`, `calibration.set.delete`, `calibration.source.add { …, source }`, `calibration.source.remove`, `calibration.lap.exclude` / `include { …, source, lap }`, `calibration.override.set { …, key, value }` (number, within the key's declared range), `calibration.override.clear`, `calibration.choose { feedId, setId | null }`.

A source must be a stint of a stored session on the set's track, of the feed's player car or its teammate (our cars' data only: rivals' wear and fuel are hidden under realism). A source whose stint is no longer in its session's projection (after a rebuild, C61, or a deleted session) stays in the set, marked `missing` in the panel, and is left out of every aggregate.

### 3.2 The priors store

- Each estimation unit declares its priors in its own folder (`priors.ts`): `definePriors(unit, { entries: { key: { version, range, aggregate, residual } }, candidate })`, where `aggregate(sources: StoredSource[], overrides, config) → Known<value>`, `residual(sourceValue, setValue) → Known<number>` and `candidate(source: StoredSource, config) → boolean`; a `StoredSource` is the source's stint with its laps (minus excluded ones), its session's weekend phase, stops and track file, read from the stored projection (C34). `config` is the unit's effective config (C47), so an aggregate uses the same thresholds as the unit. The features register them (`priors: [...]` in `register.ts`, C63), as they register config.
- The bridge holds the store in `PITWALL_DATA_DIR/priors.sqlite`: per set and key, the value, its version and the inputs' fingerprint (sources, overrides, config). A version or fingerprint mismatch recomputes the entry. It recomputes on a calibration edit, at session end (the candidates change), and on a rebuild (C61).
- Per source it also keeps the source's own value (`aggregate` over that one source) and its `residual` against the set's value, for the panel (drift, A23).
- Suggestions: the stints of stored sessions on the track, of our cars, not in the set, that some unit's `candidate` accepts (`degradation`: at least `minSourceLaps` 5 `forPace` laps); this weekend's first, then newest first. The bridge only orders them.

### 3.3 Choosing a set for a run

- **Preselection** at session start: the track's set with the newest `lastUsedAt`; else the set with the newest source session; else none (`view.priors` `notApplicable`, every estimate starts from the track file's defaults, `ᵈ`).
- **Snapshots:** the run starts on the preselection's snapshot at once (C62a). The sidecar `<recording>.priors.json` (C59) holds `{ start: fingerprint | null, snapshots: { [fingerprint]: entries } }`, written at session start and added to on each pick. A recording without it replays with `view.priors` `notApplicable` (every existing recording).
- **The prompt:** when a new session starts, the UI opens an overlay listing the track's sets, the preselection marked, and `defaults`. Each entry invokes a command (C72), one per set of the session's track, `calibration.choose.<setId>`, and `calibration.choose.defaults`, which sends the uiAction `calibration.choose`. The bridge adds the set's current snapshot to the priors sidecar and hands the runner the decision `calibrationChosen { setId | null, snapshot: fingerprint | null }`; the decision recorder appends it at the current frame (C10, C22, C76) and the bridge writes it to the decisions sidecar. A pick on the grid or in the formation lap counts like any other (C29 as changed in §2). Closing the prompt keeps the preselection. The command `calibration.pick` opens the prompt at any time.
- A flashback that voids the decision voids the switch (C27a): `view.priors` follows the projection.
- **Top bar:** the active set's name, or `defaults`; a click invokes `calibration.pick`.

## 4. Estimation units

All three are quick calculators (C41): from scratch over the projection they cost microseconds per frame on the long-race builder, so the C31 exception is not needed. Each holds a behaviour table over the sub-machines it reads (C44).

### 4.1 `degradation`

- **Model:** a Kalman filter per car and stint (Cappello & Hoegh). State: tyre pace `α` and degradation per lap `ν`; observation: the fuel-corrected lap time `lapTimeMs − γ · fuelKg`, `γ` = `gammaMsPerKg` 30 (Bonomi et al. 2023). Fuel from the lap record (`fuelAtStartKg`). Hidden (a rival under realism): in the race, our car's fuel at the start of the same race lap (every car starts the race near the same load and burns at a similar rate); past our car's last lap, its last value minus its `fuel` rate per lap since, else `fallbackBurnKgPerLap` 1.8. In practice and qualifying a rival's load cannot be known: its stints are fitted without the correction and marked `fuelCorrected: false`.
- **Laps:** `forPace` laps only (`lap-classes`). A lap slower than the prediction by more than `outlierSd` 2.5 sd is down-weighted (its observation noise × `outlierNoiseFactor` 10); a faster lap never is.
- **Stint start:** the prior from `view.priors` for the stint's compound (`α` offset, `ν` with sd), else the track file's compound offset with `ν` `defaultNuMsPerLap` 60 and sd `defaultNuSdMs` 60 (`ᵈ`).
- **Basis:** `wear` when the car's wear is visible, else `age`.
- **Output per car and stint:** `basePaceMs`, `nuMsPerLap` with `sdMs`, basis, `fuelCorrected`, wear rate per corner (`per-lap-rate`), source (`session` / `calibration` / `default`, decided here by the rule in 4.4, with the blend parts), and per lap `used | downWeighted | excluded(reason)`.
- **Cadence:** `frame`, reads `laps`, `stints`, `pitStops`, `decisions`: it runs on the frame one of them changes (every completed lap of any car: the lap is the finest correct input, A2; and a calibration pick or its void).
- **Priors entries:** per compound `degradation.alphaOffsetMs.<compound>`, `degradation.nuMsPerLap.<compound>`, `degradation.nuSdMs.<compound>`: the filter run over each source stint, pooled by inverse variance; overrides replace the pooled value. `residual`: the source's value minus the set's, in sd of the set's value. `candidate`: a stint of at least `minSourceLaps` 5 `forPace` laps.

### 4.2 `tyre-life`

- **Current set, per car:** laps to the limit. Wear basis: per corner the laps until `wearLimitPct` 70 at its rate (today's `tyre-wear` logic, moved here); the worst corner limits. Age basis: the age at which `ν · age` reaches `ageLossLimitMs` 2000, minus the current age.
- **Fresh-set life per compound:** from the priors' wear rates (laps from 0 to the limit), else from `ν` (age basis), else `unknown('insufficientData')`. For 4.2's pit window.
- **Cadence:** `{ hz: 4 }` as `tyre-wear` today, reads `laps`, `stints`, `tyres`, car status, `decisions` and `degradation`: `tyreWear.car` keeps its rate, and the live wear moves between laps.
- **Priors entries:** `tyreLife.wearPerLapPct.<compound>.<corner>`; overrides `tyreLife.wearLimitPct`, `tyreLife.ageLossLimitMs` (per set). `residual`: the source's value minus the set's.
- **The port (C43):** `tyre-wear` becomes a thin analysis that publishes `tyreWear.car` from `tyre-life`'s output, the topic unchanged; its readers (`alarms`, the corner block, the tyre-life bar) do not change. Its tests are ported to `tyre-life` where the judgement moved, never dropped (C82). This also makes `tyre-wear` an analysis, as its topic requires (C42).

### 4.3 `pit-loss`

- **Per stop of every car:** loss = in-lap + out-lap − 2 × the car's median `forPace` lap of the `referenceLaps` 3 before the stop (TUM); the stationary time above the session's median stationary time is removed and kept apart. A stop without a clean reference is left out and counted (`noReference`).
- **Condition:** the stop record's `flag` (green, VSC, SC).
- **Per condition:** `(n · sessionMedian + k · prior) / (n + k)`, `k` = `priorWeightStops` 2, `n` the session's stops of that condition; the prior is `view.priors`' value, else the track file's default. Source and parts carried (`2 stops + calibration`).
- **Priors entries:** `pitLoss.ms.<condition>`: the median over every stop of the sessions that give the set a source, each session counted once however many of its stints are sources (a visit that ends in the garage is no stop record, so practice adds only real stops); overrides replace it. `residual`: the source session's median minus the set's.
- **Cadence:** `frame`, reads `pitStops`, `laps`, `decisions`.

### 4.4 Source badge (kit piece)

One cell after a value that rests on a prior. The calculator decides the source and the analysis topic carries it with its parts and hover text (C43); the badge only maps it to a mark (C65). No mark = measured this session (the session's share of a blend above half: for `pit-loss` `n / (n + k)`, for `degradation` the share of `ν`'s posterior precision that its laps added, `1 − posteriorVar / priorVar`); `ᶜ` = calibration (hover: the set's name and its sources); `ᵈ` = default (hover: the track file's source note). Every badged value carries the hover with its parts. Replaces the mockups' `ˢ` (A27).

## 8. Testing

- **Contract:** the guarded views (C41), behaviour tables (C44), presentation tables of the displays that read situations (C66) through the generic completeness tests.
- **`degradation`** (builders): a synthetic stint with constant `ν` recovers it within 10 %; a slow outlier is down-weighted, a fast lap never; a stop starts the next stint from the prior; without priors the default with source `default`; a rival under realism has basis `age`, takes our car's fuel in the race and is `fuelCorrected: false` in practice.
- **`tyre-life`**: the ported `tyre-wear` cases; the age basis; fresh-set life from priors and without.
- **`pit-loss`**: TUM arithmetic on a hand-built stop; the stationary correction; `noReference`; the blend at n = 0, 1, 2; a segment test on a real green stop (loss exceeds the pit-lane time) and one on a VSC or SC stop (classed by condition) (C84).
- **Calibration store** (bridge, temporary data dir): aggregate determinism; a version or fingerprint mismatch recomputes; deleting the store loses nothing; every uiAction's validation and rejection; preselection order; a source missing after a rebuild is marked and left out; one session's stops count once in `pitLoss.ms`.
- **Decisions:** a replay with a decisions and a priors sidecar equals the live run (C38, stream hash); a pick re-runs every priors reader on its frame; a pick in the formation lap is visible in the projection and changes `view.priors` (C29); a flashback that voids a `calibrationChosen` restores the earlier priors (C27a, C33 property); a recording without a priors sidecar runs on `notApplicable`; the guarded view throws on `view.priors` without `decisions` read (C41); no accumulator reads priors (type).
- **Budgets** on the long-race builder: each calculator < 1 ms per lap update.
- **UI:** component tests for the panel's actions, the prompt and the top-bar name; one screenshot baseline per new display size within the budget (`SCREENSHOT_BUDGET`).
